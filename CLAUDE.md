# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Root package manager is Yarn (Berry, `yarn@4.5.1` via corepack — do not use npm/pnpm lockfiles at the root). `functions/` is a separate **npm** project (its own `package-lock.json`); run npm there, not yarn.

- `yarn dev` — Vite dev server on port 3001 (Vite silently picks the next free port if 3001 is taken — check its output, or pass `--port N --strictPort`, before pointing tests at a URL)
- `yarn build` — type-check (`tsc`) then build the production bundle
- `yarn lint` — ESLint over `src`, zero warnings allowed (currently clean)
- `cd functions && npm run build` — compile Cloud Functions (`tsc` → `functions/lib`)
- `firebase deploy --only firestore:rules,firestore:indexes,functions,storage` — deploy rules and functions to the `gen-papers` project. The Firebase project belongs to `contactogeniality@gmail.com`; pass `--account contactogeniality@gmail.com` (or `firebase login:use`) if the CLI's default account differs. Note the bare `storage` target, not `storage:rules` — firebase-tools 15.4.0 rejects `storage:rules` with "Could not find rules for the following storage targets: rules" (it parses the part after `:` as a deploy target name, which only exists if bound via `firebase target:apply`); Storage has no rules/indexes split the way Firestore does, so `--only storage` alone deploys `storage.rules`.

There is no test runner. Local end-to-end runs use the Firebase emulators with an isolated `demo-` project so nothing touches production:

```
FUNCTIONS_DISCOVERY_TIMEOUT=60 firebase emulators:start --only firestore,functions,auth,storage --project demo-gen-papers
VITE_FIREBASE_PROJECT_ID=demo-gen-papers VITE_USE_FIREBASE_EMULATORS=true yarn dev
```

`FUNCTIONS_DISCOVERY_TIMEOUT` is needed on this Windows machine: the CLI's default 10 s wait for function discovery times out (`User code failed to load ... Timeout after 10000`) although the code itself loads in under a second — the same applies to `firebase deploy`. Emulator data is per project id, so seed data and the app must use the same one (`demo-gen-papers`). Emulator ports are in `firebase.json`; Firestore needs Java. To use the admin panel locally, create a user in the Auth emulator and an `admins/<uid>` doc in the Firestore emulator. Vite's first dev load is slow on this machine (minutes on a cold cache); give browser automation generous timeouts.

## Architecture

"Gen. Papers": a multi-event conference poster (paper) viewing/voting SPA with an embedded admin panel — Vite + React 18 + TypeScript + Mantine 7 — backed by its own Firebase project (`gen-papers`: Firestore + callable Cloud Functions + Auth for admins). It was split off from a shared ACHO Mongo backend (`achoapi.geniality.com.co`); that split is complete — nothing in this repo calls that API anymore, and `axios` is not a dependency.

### Firestore model (security rules in `firestore.rules`)

```
events/{eventSlug}                        name, votingOpen, bannerUrl, backgroundUrl, screensaverEnabled, screensaverIdleSeconds, screensaverPhotoDurationSeconds, searchExplanationsEnabled, touchKeyboardEnabled, publicStyle
                                           (doc id = URL slug; bannerUrl/backgroundUrl are optional per-event image URLs, null = site defaults; screensaver fields default to off/120s/8s, see below; touchKeyboardEnabled defaults to **on** — a missing field counts as true; publicStyle is "glass" (default, also when missing) or "classic")
  fields/{fieldId}                        label, type ("text"|"number"|"select"|"multiselect"), order, required, filter ("none"|"cards"|"buttons"), revealAfterPrevious, showOnCard, options[{id, name, color, order}]
                                           (the event's configurable paper attributes, see "Campos por evento" below; public-read, admin-write)
  papers/{id}                             title, authors[], institution, urlPdf, urlVideo, attributes{fieldId: value}, voteCount, viewCount, downloadCount
  categories/{id}                         LEGACY (name, color, order): migrated into a "categoria" select field; kept, together with the old categoryId/theme/year/country/identificationCode paper fields, only until the previous frontend is gone
  paperSearchIndex/{id}                   status ("processing"|"ready"|"partial"|"error"; legacy "unsupported"), urlPdf, extractedText, textLength, embedding[], embeddingModel, embeddingDim,
                                           error, lastError, pdfFailure, failureCount, signature, indexVersion, extractorVersion, updatedAt, lastAttemptAt
                                           (doc id = paper id; public-read, function-only write — see "Búsqueda inteligente" below)
  voters/{idNumber}                       idNumber, fullName, active (roster; doc id = cédula; admin-only)
  votes/{idNumber}                        paperId, castAt            (doc id = cédula → one vote per person; nobody can write from the client)
  metricsDaily/{yyyy-mm-dd}               date, views, downloads, papers{paperId:{views,downloads}}   (admin-read, function-only write: incrementPaperMetric acumula por día en zona America/Bogota; resetPaperMetrics los borra; alimenta las gráficas de `MetricsCharts.tsx` en /results, hechas con @mantine/charts)
  screensaverItems/{id}                   type ("image"|"video"), url, order, fit ("cover"|"contain", default "cover")   (public-read like categories/papers; the idle-screensaver's photo/video rotation)
admins/{uid}                              email                      (existence of the doc = is admin; collection name is `admins`, plural)
```

- **Campos por evento**: apart from the fixed title/authors/institution/PDF/video (needed by search, indexing and voting) and the function-written counters, every paper attribute is a per-event field (`src/services/firestore/fieldService.ts`). `papers.attributes[fieldId]` holds a string (text), number, an option id (select) or an array of option ids (multiselect); option ids are stable, so renaming an option or field never touches papers. Options live inline in the field doc (few per field) and are rewritten whole by `saveFieldOptions`. Deleting a field/option also strips it from its papers in the same chunked batch (`deleteFieldAndValues`/`deleteFieldOption`). A field's type is immutable after creation (stored values wouldn't make sense under another type). E.g. `aquaepi` only has Año/País/Código; `congreso-nacional-acho-2026` has Especialización (cards) + Tipo de estudio (buttons, revealAfterPrevious) + Año/País. The migration from the old fixed fields was a one-off REST script (not in the repo) using deterministic ids: `categoria` (option ids = old category doc ids, so nothing was reclassified), `tipo-estudio`, `tema`, `anio`, `pais`, `codigo`.
- Public visitors read events/fields/papers (including `voteCount`); voters and votes are admin-read only. Admins (any admin, any event) write events/fields/papers/voters directly from the client under the rules. `voteCount` and everything under `votes/` are written **only** by Cloud Functions (Admin SDK) — rules forbid client writes so a vote (vote doc + counter) stays atomic.
- Cloud Functions (Node 22, region `us-central1`; `functions/src/index.ts` re-exports everything, bodies live under `functions/src/lib/` and `functions/src/search/`): `castVote({eventSlug, idNumber, paperId})` (transaction: event open, voter exists & active, paper exists, no previous vote; errors are `HttpsError`s with Spanish messages, `already-exists` carries `details.paperTitle`), `resetVotes({eventSlug})` (admin-only; deletes all votes, zeroes `voteCount`) and `grantAdmin({email})` (admin-only; **no UI yet**). Search-indexing functions are documented under "Búsqueda inteligente" below.
- The first admin must be bootstrapped by hand: create the Auth user, then create `admins/<that UID>` in the console (`grantAdmin` requires already being admin).

### Firebase Storage (security rules in `storage.rules`)

- Papers' PDFs live at `events/{eventSlug}/papers/{timestamp}-{sanitizedFileName}`, event banner/background images at `events/{eventSlug}/images/{kind}-{timestamp}-{sanitizedFileName}`, and screensaver photos/videos at `events/{eventSlug}/screensaver/{type}-{timestamp}-{sanitizedFileName}`, all in the project's default bucket (`gen-papers.firebasestorage.app`, already provisioned). Public read; write/delete gated by an `isAdmin()` check — `request.auth.token.admin == true`, a **custom auth claim** (not a Firestore cross-service rule) that `grantAdmin()` sets via `setCustomUserClaims` alongside creating `admins/{uid}` — no signed URLs, no Cloud Function in the upload path itself, no extra IAM grants needed. Also enforced in rules: papers need `contentType == 'application/pdf'` and size `< 30MB` (mirrored client-side as `MAX_PAPER_FILE_BYTES`); images need `contentType.matches('image/.*')` and size `< 5MB` (mirrored as `MAX_EVENT_IMAGE_BYTES`); screensaver media needs `contentType` matching `image/.*` or `video/.*` and size `< 150MB` (mirrored as `MAX_SCREENSAVER_MEDIA_BYTES`) — all three limits enforced client-side too, in `storageService.ts`, so bad files are rejected before the upload starts, not just by the rule. Deploying rule changes needs `firebase deploy --only storage` — a bare `storage:rules` target isn't valid on this CLI version, see the Commands section.
- `Storage list is not granted` — rules only cover per-object `get`/`write`/`delete`, not bucket-level `list`. Don't rely on the Storage REST `list` endpoint (even from tooling) expecting it to work; use the Admin SDK (bypasses rules, e.g. in a seed/debug script) if you need to enumerate objects.
- `src/services/storageService.ts`: `uploadPaperPdf(eventSlug, file, onProgress?)` / `uploadEventImage(eventSlug, "banner"|"background", file, onProgress?)` / `uploadScreensaverMedia(eventSlug, "image"|"video", file, onProgress?)` (resumable upload, returns `{promise, cancel}`; promise resolves to the public download URL) and `deletePaperPdf(url)` / `deleteEventImage(url)` / `deleteScreensaverMedia(url)` (all three aliases of the same best-effort delete helper; silently no-ops on a URL that isn't a Storage download URL, e.g. an externally-hosted file from before this feature).
- `AdminPapers.tsx`'s paper form uploads directly to Storage (a `FileInput`, not a URL text field): required on create, optional on edit (leaving it empty keeps the paper's current `urlPdf`, shown as a "Ver archivo actual" link). Replacing a file on edit deletes the previous Storage object after the Firestore write succeeds. The papers **bulk upload** (Excel) still takes a `urlPdf` column as a plain URL — Excel rows can't carry file attachments, so bulk-imported papers are expected to already be hosted somewhere (e.g. a URL an admin uploaded through the single-paper form and copied, or an external host).

### Búsqueda inteligente (semantic + exact search over PDF content)

- Every paper is indexed into `events/{eventSlug}/paperSearchIndex/{paperId}` (doc id = paper id, see Firestore model above): its PDF's extracted text (capped ~20k chars) for exact-term matching, plus a Gemini embedding for semantic matching. Since `INDEX_VERSION` 2 (`functions/src/lib/paperMetadata.ts`) the embedding input is **title + the event's field values ("Label: value", option names; number fields skipped) + PDF text**, truncated to `MAX_EMBEDDING_INPUT_CHARS` (8k), with the title also passed as the API's `title` param; authors/institution are left out on purpose (exact search covers them, in an embedding they'd only add noise). Indexing is fully automatic — no admin action needed for it to happen, though a manual retry/backfill button and a nightly retry exist (see below).
- Index statuses: `ready` (PDF text + metadata), `partial` (the PDF gave no text — scanned, no PDF, download failed — so the embedding comes from title + fields only and the paper still takes part in semantic search; `pdfFailure` is `"unsupported"` if retrying is pointless or `"error"` if it may be transient), `error` (embedding failed and there was no previous embedding of the same PDF), `processing` (only set on a doc that has no embedding yet). **A failed re-index never degrades a working index**: if the doc already had an embedding of the same PDF, `recordFailedAttempt` only bumps `failureCount`/`lastError`/`lastAttemptAt` and leaves status, embedding, text and `signature` alone (the stale signature is what makes the nightly retry pick it up again; the admin badge shows it outlined with a `*`). Likewise a transient PDF download failure falls back to the stored text of the same `urlPdf`. Clients decide semantic participation with `hasEmbedding()` and exact body search with a non-empty `extractedText` (`PostersContext.tsx`), **not** by status — the pre-v2 frontend required `status === "ready"`, so docs left in `error` dropped out of the live site's search. Legacy `unsupported` docs (v1, no embedding) get migrated to `partial` by the nightly retry.
- `functions/src/search/indexPaperSearchTrigger.ts` (`indexPaperSearch`, a **Firestore `onDocumentWritten` trigger** on `papers/{paperId}` — the first non-callable trigger in this codebase) fires on every paper create/update/delete, including the `voteCount` increment `castVote` does on every vote cast; it no-ops unless the paper's `indexSignature` (sha1 of `INDEX_VERSION` + `urlPdf` + title + canonicalized `attributes`) changed (or the doc was deleted, which deletes the matching `paperSearchIndex` doc). A title/field-only change reuses the stored extracted text and only re-embeds. Renaming a field or option (in `fields/`) does **not** re-index — use "Reindexar todo". It writes only to the sibling `paperSearchIndex` collection, never back to `papers/{paperId}`, specifically so it can't re-trigger itself.
- `functions/src/search/indexPaper.ts` (`indexPaper(eventSlug, paperId, {refetchPdf?})`) is the shared core: reads the paper itself, fetches the PDF by URL (works for both Storage-hosted and bulk-imported external URLs; skipped when the stored text is reusable — same `urlPdf`, same `EXTRACTOR_VERSION`, `refetchPdf` false), extracts text via `functions/src/lib/pdfText.ts` (pdfjs-dist, no OCR), then embeds via `functions/src/lib/gemini.ts` (`embedText`, model `gemini-embedding-001`, `taskType: "RETRIEVAL_DOCUMENT"` when indexing vs `"RETRIEVAL_QUERY"` for a search query, 768-dim output; throws on a vector of the wrong dimension instead of storing it). **Gemini quota:** the API key is on the **free tier: 30 000 embedding tokens/minute per project, shared with visitors' queries** (a poster is ~2–2.7k tokens, so ~10 posters/min). A first v2 "Reindexar todo" of hematología (111 papers, 5 in parallel) hit it: 48 × `429 RESOURCE_EXHAUSTED` (`EmbedContentTokensPerMinutePerProjectPerModel-FreeTier`). So document embeddings go through `reserveTokens` (per-instance sliding-minute budget, `GEMINI_EMBED_TOKENS_PER_MINUTE` env var in `functions/.env`, default 24 000, tokens estimated as chars/3) and `withRetries` waits on a 429 for the API's `retryDelay` or 10 s/20 s/30 s… (5 attempts, ≤60 s each); a visitor's query (`RETRIEVAL_QUERY`) and explanations skip the budget and retry once for ≤2 s. Paid tier (Tier 1) lifts the limit — then raise the env var. The trigger's timeout is 300 s to allow those waits. Function logs: `firebase functions:log --project gen-papers --lines 60` (`--only <name>` only shows audit entries for v2 functions; large `--lines` values fail). It never throws itself — every path ends in a durable write with a Spanish `error` message. The final write goes through `commitIfCurrent`: a transaction that re-reads the paper and only writes if its `indexSignature` still matches what was indexed (otherwise the newer trigger owns the result — a slow, older run can't overwrite a newer PDF's index), and deletes the index if the paper was deleted meanwhile (no orphans).
- Text extraction (`pdfText.ts`, `EXTRACTOR_VERSION` 2) joins pdfjs text items **by position** (`joinTextItems`: touching items on a line are the same word, e.g. Canva's "S"+"exo"; super/subscripts and real gaps get a space), then `cleanExtractedText` re-joins line-break hyphenation, repairs letter-spaced headings (pdfjs itself returns "T R O M B O C I T E M I A" / "C ON GR ES O"; runs are re-segmented into words with the document's own vocabulary + `BASE_VOCABULARY` + the paper title) and kerning-split words ("t ransformaciones" is joined when the whole word appears elsewhere in the document). When changing this logic, bump `EXTRACTOR_VERSION` so stored texts aren't reused.
- `pdfjs-dist` and `@google/genai` are both **ESM-only** packages; `functions/tsconfig.json` uses `"module": "node16"` (not the previous `"commonjs"`) specifically so dynamic `import()` of them survives compilation as a real ESM import instead of being downlevelled to a `require()` that would crash at runtime. Both are loaded lazily via dynamic `import()` inside `lib/pdfText.ts`/`lib/gemini.ts`, not static imports.
- `functions/src/search/embedSearchQuery.ts` (`embedSearchQuery({query})`, public callable, no auth — consistent with the rest of the public site — capped at 300 chars) turns a visitor's search text into an embedding on demand; the client then ranks papers **client-side** via cosine similarity (`src/utils/vectorMath.ts`) against each paper's already-synced `embedding`, the same 100%-client-side-filtering pattern `PostersProvider` already used — there's no Firestore native vector search / vector index involved. Cosines from `gemini-embedding-001` sit in a narrow band (an unrelated query still scores ~0.5 against every paper; on-topic ones reach ~0.6–0.77), so a low fixed threshold matches every paper — the original 0.5 returned all 16 `aquaepi` papers for any query. `PostersContext.tsx` therefore keeps a paper only if it passes an absolute floor (`SEMANTIC_THRESHOLD`, 0.62) **and** is within `SEMANTIC_RELATIVE_WINDOW` (0.06) of that query's best score. Calibrated on the `aquaepi` event; retune both constants if conceptual search returns too much or too little.
- `functions/src/search/reindexPaperSearch.ts` (`reindexPaperSearch({eventSlug, paperId?})`, admin-only callable) re-runs `indexPaper` (always `refetchPdf: true`) for one paper or (no `paperId`) the event's papers, 5 at a time (`lib/concurrency.ts`). A whole event doesn't fit in one call at the free-tier pace, so each call works for `TIME_BUDGET_MS` (6 min), skips papers already attempted in the run (`lastAttemptAt >= runStartedAt`) and returns `{processed, remaining, runStartedAt, summary}`; `reindexAllPaperSearch` (`searchQueryService.ts`) loops with the same `runStartedAt` until nothing remains. Exposed in `AdminPapers.tsx` as a per-row retry icon (on `error`/`partial`/`unsupported` or a kept-previous index) a "Reindexar todo" button (shows "Reindexando… x de y", then the summary), and "Reindexar con error (N)" — client-side only, no function change: it calls `reindexPaperSearch` once per paper, **sequentially** (each call goes through the instance's token budget), for papers with no index, status `error`/`unsupported`/`pending`, or a `lastError` (kept-previous index or transient PDF failure); scanned PDFs (`partial` without `lastError`) are excluded since retrying can't help; the page also shows a coverage alert (papers without an embedding, papers indexed from metadata only).
- `functions/src/search/retryPaperSearchIndex.ts` (`retryPaperSearchIndex`, **scheduled**, daily 03:00 America/Bogota — needs Cloud Scheduler, which `firebase deploy` enables) walks every event and (re)indexes: papers with no index doc, `processing` docs stuck >1 h, and — while `failureCount` < `MAX_AUTO_RETRIES` (5) — docs whose stored `signature` differs from the paper's current one (version bump, a failed re-index that kept the previous index, a missed trigger), `error` docs and `partial`+`pdfFailure: "error"` docs. It works for `TIME_BUDGET_MS` (7 min, ~60 papers at the free-tier pace) and leaves the rest for the next night ("Reindexar todo" does it immediately). It also deletes orphan index docs.
- `scripts/search-eval/` (`evaluate.mjs` + `queries/<event>.json`, see its README): offline evaluation of semantic search quality (precision/recall per query, `--sweep` over threshold/window, `--candidates` to build query sets) against production data through public endpoints only; it reads the thresholds straight from `PostersContext.tsx`. The oncology query set is an unvalidated keyword-generated draft. Run it before/after changing thresholds or the indexing pipeline. Baseline on the v1 index (oncology, draft set): precision 79%, recall 90%, F1 82%.
- `functions/src/search/explainSearchMatch.ts` (`explainSearchMatch({eventSlug, paperId, query, language})`, public callable, no auth, query capped at 300 chars) returns a one/two-sentence "why did this poster match" explanation, generated by `explainMatch` in `lib/gemini.ts` (`EXPLANATION_MODEL`, the `gemini-flash-lite-latest` alias, temperature 0) from the paper's title, its field values ("Label: value", option ids resolved to names, via the shared `describeAttributes` in `lib/paperMetadata.ts`) and authors plus its indexed text (capped at `MAX_EMBEDDING_INPUT_CHARS`). It **refuses with `failed-precondition` unless the event has `searchExplanationsEnabled: true`** — the admin switch (in `AdminEventLayout`, next to the voting switch, default off) gates the cost server-side, not just the button in the UI. This is the "LLM layer over vector retrieval" step: the cosine ranking itself stays 100% client-side and only says *how close*, never *why*.
- The `GEMINI_API_KEY` secret (Google AI Studio Developer API key, not Vertex AI) must exist before deploying (`firebase functions:secrets:set GEMINI_API_KEY`); it's bound via `defineSecret`/`secrets: [...]` on all five search functions, never exposed as a `VITE_*` client var.
- Frontend: `PostersProvider` additionally subscribes to `paperSearchIndex` (`src/services/firestore/paperSearchIndexService.ts`) and exposes `searchMode` (`"exact" | "semantic" | "both"`, `usePosters.ts`; **defaults to `"both"`**, since exact covers acronyms/proper names that semantic misses) alongside `searchTerm` (the raw field text) and `activeSearchTerm` (the search actually applied: `searchTerm` once it has `MIN_SEARCH_LENGTH` = 3 non-blank characters, `""` below that — so 1–2 letters don't filter, highlight, count as a selection for `selectionRequired`, show "Resultados", hit analytics or request an embedding, in any mode). Typing debounces (via `lodash.debounce`, previously an unused dependency) a call to `embedSearchQuery` (`src/services/firestore/searchQueryService.ts`) when the mode isn't `"exact"`. Exact mode now also matches each paper's indexed `extractedText`, not just title/authors; results are scored and sorted rather than just filtered. An exact match is title > author > body: title and author match when they contain **all the query's meaningful words** in any order (`searchWords`/`containsAllWords` in `utils/text.ts`, which drop Spanish/English stopwords like "de", "en"), while the PDF body still needs the whole phrase (single words appear in almost every 20k-char body). `"exact"` mode orders by that level (ties alphabetical); `"both"` orders by **cosine + `EXACT_BONUS`** (title/author +0.08, body +0.03; `SEMANTIC_THRESHOLD` stands in for a missing cosine), so results within each match type come by affinity, not alphabetically, and a passing body mention no longer always beats a poster whose whole topic is the query. An exact match always gets in, a semantic-only one only above the cutoff. Bonuses were calibrated by simulating real oncology queries ("inmunoterapia", "supervivencia en cáncer de pulmón", "osimertinib"): same result sets, better order. Comparison goes through `normalizeSearchText` (`utils/text.ts`: lowercase, no accents, and **whitespace runs collapsed**) on both the term and the text — PDF-extracted text is full of multi-space runs (italics, columns: `"Giardia   spp."`), which used to make a phrase like "giardia spp" miss a body that literally contained it. `PostersProvider` precomputes each ready paper's collapsed/folded body once per index change (`bodyByPaperId`), not per keystroke. `normalizeText` (no collapsing) is still what the admin panel uses. `PosterList.tsx` exposes the mode as a `SegmentedControl` with a localized caption per mode (`posterList.searchModeCaption.*` in `es.ts`/`en.ts`). In `"exact"`/`"both"` mode the cards highlight each meaningful query word in title and authors (`HighlightedText`, built on `findWordRanges`/`findMatchRanges` in `utils/text.ts` — accent/case-insensitive like the search itself, so Mantine's own `Highlight` isn't used); a paper whose only match is in the PDF body shows a snippet (`getBodySnippet` from the context) so a result is never unexplained. `totalResults`/`posters.length` feed the "Resultados: x de y" line shown while a search term is active (hidden while a semantic query is in flight, since results aren't valid until its embedding arrives). Poster card titles clamp at 4 lines. Cards that appear **only by meaning** (`semantic` mode, or `both` without an exact match — the set is computed in the results `useMemo` as `semanticOnlyIds`) get a "¿Por qué este resultado?" button (`MatchExplanation.tsx`) when `canExplainMatch(paperId)` is true, i.e. the event's `searchExplanationsEnabled` is on and the query embedding isn't in flight. The explanation is requested **on click**, not on listing (so only opened ones cost a Gemini call), through `explainSearchMatch` in `searchQueryService.ts`, which memoizes per (event, paper, language, query); it's labeled as AI-generated and its strings live under `posterList.explanation.*` in `es.ts`/`en.ts`.

### Frontend data flow

- `src/services/firebaseConfig.ts` — initializes the app from `VITE_FIREBASE_*` env vars (see `.env.example`; real values in the git-ignored `.env.local`) and exports `auth`, `db`, `functions`. With `VITE_USE_FIREBASE_EMULATORS=true` in dev it connects to the local emulators.
- `src/services/firestore/*Service.ts` — one file per resource (event, field, paper, paperSearchIndex, voter, vote, admin). Reads are live `onSnapshot` subscriptions that normalize/validate documents at the boundary; writes are plain Firestore writes, with `batch.ts` chunking bulk writes into ≤450-op batches. `voteService.castVote` wraps the callable and throws a typed `VoteError` (`not-found | already-exists | failed-precondition | unknown`); `resetVotes` wraps the admin callable. `searchQueryService.ts` wraps the `embedSearchQuery`/`reindexPaperSearch` callables (see "Búsqueda inteligente" below).
- Contexts follow a split that keeps `react-refresh` lint happy: the context object + hook live in `useX.ts`, the provider component in `XContext.tsx`.
  - Public: `PostersProvider` (`PostersContext.tsx`, hook `usePosters`) is per event: subscribes to the event, its `fields`, papers, `screensaverItems` and `paperSearchIndex`, and does all filtering client-side (accent-insensitive search on title/authors/PDF text, one multi-select filter per list field whose `filter` isn't `none` — options toggle on/off, there is no "Ver todos"; an empty filter doesn't restrict, but while the event has filters and none has a selection (and there is no search term) `selectionRequired` is true and `PosterList` shows a "Selecciona … para ver los pósters" prompt instead of the list; an icon inside the search input opens `AdvancedSearchModal` (title, authors, PDF text, plus one control per event field: list fields share the filters' selection via `setFieldSelection`, number fields are an inclusive from/to range, text fields are "contains"), whose criteria (`advancedSearch`) are ANDed with search and filters and also count as a selection for `selectionRequired` — plus optional semantic ranking, see "Búsqueda inteligente"; each filter's counts ignore that filter but respect search and the other filters; a field with `revealAfterPrevious` only appears once the visitor has toggled an option in the previous filter, and doesn't filter while hidden; the first `cards` field colors the poster cards; page size starts at 10 and scales up on large/TV screens, see below). Exposes `eventStatus` (`loading | ready | not-found | error`).
  - `src/hooks/useIdleTimer.ts` (`useIdleTimer(timeoutSeconds, enabled): boolean`) tracks visitor inactivity via `window`-level mouse/keyboard/touch/scroll listeners; `EventGate` (`EventLayout.tsx`) mounts `ScreensaverOverlay` as a sibling of `PublicShell` (not inside it — `PublicShell` is also used by `NotFoundPage`, which has no `PostersProvider`) whenever `event.screensaverEnabled` and there's at least one `screensaverItem`, so it covers both the poster list and the poster detail page. The overlay rotates photos (auto-advance after `screensaverPhotoDurationSeconds`) and videos (advance on `onEnded`; a single video item `loop`s instead, since `onEnded` re-setting the same index wouldn't re-render). Any click/touch/key dismisses it. Because it unmounts on the waking `touchstart`/`mousedown`, the `click` of that same tap would land on whatever is underneath (e.g. a poster card, which navigates): the overlay's `onPointerDown` calls `swallowNextClick`, a capture-phase `window` listener that cancels the next click (≤1 s). Verified on a real build with CDP touch events (finger down, 150 ms, up): without it the waking tap opened the poster. `PosterDetail.tsx` has a `window` blur/focus-based workaround that synthesizes activity while focus sits inside the cross-origin PDF iframe, so reading a poster doesn't get interrupted (best-effort — the iframe's own activity can't bubble to `window`).
  - `src/hooks/useBannerExpanded.ts` (`useBannerExpanded(idleSeconds): boolean`, same `window`-level activity events as `useIdleTimer` but inverted polarity — starts `true`) drives `PublicShell`'s banner size: large first impression before any interaction, compact once the visitor starts using the page, back to large after `idleSeconds` of inactivity. `EventLayout.tsx` passes `event.screensaverIdleSeconds` as that duration (reusing the screensaver's own idle setting, independent of whether the screensaver itself is enabled); `PublicShell` falls back to a 20s default when no event is available (e.g. `NotFoundPage`). Both banner sizes are CSS `clamp()` (never unbounded `height: auto`), `object-fit: contain` and horizontally centered, so a banner that doesn't match the ~10:1 recommended aspect ratio is never cropped, just letterboxed. A **tap collapses the banner only after the finger lifts** (`pointerup` + 350 ms; `mousemove`/`scroll`/`keydown` still collapse immediately, touch-compat `mousemove`s are ignored): collapsing on `touchstart` shifted the whole page ~70 px mid-tap, so on the totems every visitor's first tap missed its target (e.g. didn't focus the search input).
  - **Public style** (`event.publicStyle`, per-event "Estilo del sitio público" `SegmentedControl` in `AdminEventLayout`): `"glass"` (**default**) is a dark glassmorphism look — event background under a dark veil, translucent surfaces, white headings, filter cards/buttons and poster cards with neon borders/glows in each option's color (study-type buttons without a color get one from `GLASS_BUTTON_PALETTE`), and "Ver póster" as an outlined glowing button in the card's specialty color (`getPaperColor`: green Hematología, blue Oncología); `"classic"` is the previous light look, untouched. `PublicShell` puts `className="gpGlass"` + `data-mantine-color-scheme="dark"` on its wrapper so Mantine's dark component rules (`:where([data-mantine-color-scheme='dark'])`) apply **only inside the public site** — the admin and the global color scheme stay light; `PublicGlass.css` redefines there the variables Mantine only sets on `:root` for dark (`--mantine-color-body/default/dimmed…`, translucent) and styles inputs, segmented controls, pagination and the poster viewer toolbar. Portaled content stays light by default (tooltips, the vote modal); `AdvancedSearchModal` instead portals itself and its `MultiSelect` dropdowns into `.gpGlass` (`portalProps={{ target: ".gpGlass" }}`, only when glass) so it gets the dark look (`.gpGlassModal` rules: glass panel with a cyan glow, cyan neon "Buscar"). Note the combobox dropdown carries the opening component's class (`.mantine-MultiSelect-dropdown`), not `.mantine-Combobox-dropdown`. `PosterList` switches inline styles on `glass` (helpers `colorVar`/`tint` use CSS `color-mix()`), `TouchKeyboard` takes `dark`. Logos/banner are never restyled. Verified with screenshots of both styles (classic via a build forced to classic) at 1080×1920 and 1440×900.
  - **On-screen keyboard** (`TouchKeyboard.tsx`, mounted once by `EventLayout` only when `useIsTotem()` **and** the event's `touchKeyboardEnabled !== false` — per-event switch "Teclado en pantalla" in `AdminEventLayout`, next to the explanations one; off = fields behave as in any browser, i.e. the Windows touch keyboard if the machine has it enabled): the totems are Windows + Edge/Chrome, and rather than depend on each machine's Windows touch-keyboard settings the app brings its own (Spanish QWERTY with ñ, plus a numeric layout chosen from the field's original `inputmode`/type — the vote modal's cédula `TextInput` has `inputMode="numeric"`). It serves **any** editable input/textarea that gets focus (search, advanced-search modal, cédula) without per-field wiring: a capture-phase `pointerdown` sets `inputmode="none"` before focus so the OS keyboard doesn't also open (original kept in `data-touch-keyboard-inputmode`), keys act on `pointerdown` with `preventDefault` (the field keeps focus and caret) and write through the native `value` setter + an `input` event so React-controlled inputs see it. Fixed at the bottom, `zIndex` 1000 (above Mantine modals, below the screensaver); pads `body` while open and scrolls a covered field into view. On unmount (switch turned off or leaving totem mode with the page open) it restores every field's original `inputmode`, so the system keyboard works again. "Listo" blurs the field; `ScreensaverOverlay` also blurs the active element when it activates, so the next visitor doesn't find it open. Mantine sets `aria-hidden` on content outside an open modal, which includes the keyboard — irrelevant for touch, but Playwright's `getByRole` won't find it then (use a CSS locator).
  - **Totem mode** (`PosterList.tsx`, `isTotem` from `src/hooks/useIsTotem.ts` = `(orientation: portrait) and (min-height: 100em)`): the public site runs on 50" portrait touch totems (1080×1920). Orientation + height rather than the `tv` breakpoint, so it still applies when the browser isn't fullscreen (usable height < 1920); phones/tablets never reach 1600px tall. It enlarges the search input, mode selector, filter headings/cards/buttons and their counts, poster-card badges/title (1.5rem)/authors (clamped to 3 lines), turns "Ver póster" into a full-width filled button in the card's color, and enlarges pagination. Everywhere (not only totems): the **whole poster card navigates** on click/tap (ignoring clicks on inner `a`/`button`/`[role=button]`; the button stays the keyboard path), authors use `gray.7` instead of `dimmed`, texts that sit directly on the event background (mode caption, "Resultados") get the same translucent-white pill as the filter headings, and `capColumns` stretches filter cards when there are fewer options than columns. Verified with headless Edge + `playwright-core` screenshots at 1080×1920 and 1440×900 against a `vite build` + `vite preview`.
  - Admin: `AdminAuthProvider` (`useAdminAuth`: email/password sign-in, `isAdmin` = `admins/{uid}` exists) and `AdminEventProvider` (`useAdminEvent`: one shared subscription to the event, fields, papers, voters, votes and `paperSearchIndex` for all tabs of an event).
- The domain type `Paper` shares its name with Mantine's `Paper` component — don't import both unaliased.

### Routes (`src/App.tsx`)

- `/:eventSlug` — public: `EventLayout` (provider + shared header via `PublicShell`, which shows the event's `bannerUrl` (or the default ACHO logo, `fit="cover"` filling the header edge-to-edge) plus the `LanguageSwitcher`, + not-found/error gate + the idle `ScreensaverOverlay`, see above). `PublicShell` also owns the event's `backgroundUrl`: applied once as a fixed, full-viewport `background-size: cover` layer on its outermost wrapper, so it's behind the header (shown through a translucent+blurred strip so the banner stays legible) and every route below it, not just one page. Routes: `HomePage` (just renders `PosterList`) and `paper/:id` → `PosterDetail` (PDF in an external viewer iframe, prev/next scoped to the current page of results, vote-by-cédula modal; the vote button is disabled when `votingOpen === false`). The viewer has a toolbar with "Descargar" and "Pantalla completa": fullscreen goes through `useElementFullscreen` (native Fullscreen API, falling back to a fixed CSS overlay where it isn't supported, e.g. iPhone Safari; `ScreensaverOverlay` exits native fullscreen when it activates, since fullscreen would otherwise render above it). The viewer iframe is **PDF.js's stock viewer (v4.7)** hosted outside this repo, opened with `#zoom=page-fit` (whole poster visible; the viewer honors PDF.js hash params); touch drag and two-finger pinch inside it are handled by PDF.js itself (verified with CDP touch events). **On the totem the poster page is locked to exactly one screen**: `PosterDetail` sets `overflow: hidden` + `overscroll-behavior: none` on `<html>` and sizes `.posterViewer` to the height left below the buttons (recomputed via a `ResizeObserver` on `body`, e.g. when the banner collapses; not applied to the fullscreen overlay), restoring both on leave. Before, the page was 85vh + header (taller than the screen), so a drag inside a PDF that had nothing to scroll (poster fits at "Automatic Zoom") or hit an edge chained to the page and "the whole screen moved". Below `sm` (48em) the viewer bleeds edge to edge by cancelling the two nested `Container fluid` paddings (`PublicShell` + `PosterDetail`) with a negative margin in `PosterDetail.css` — if either container's padding changes, update that margin. "Descargar" tries a direct download first (`fetch` → blob → `<a download>` named after the poster title) and falls back to opening the PDF URL (`window.open`, then same-tab navigation if a popup blocker eats it). That only works from origins the Storage bucket's CORS allows (GET/HEAD, bucket `gen-papers.firebasestorage.app`): currently `https://genpdfviewer.netlify.app` (the PDF viewer iframe) and `https://genpapers.geniality.com.co` (production). `cors.json` at the repo root is the source of truth; to change it, edit that file and run `gcloud storage buckets update gs://gen-papers.firebasestorage.app --cors-file=cors.json` as `contactogeniality@gmail.com` (it replaces the whole array, so keep the existing origins — dropping the viewer's breaks poster loading; `gsutil` is broken on this machine, use `gcloud storage`). Any other origin — `localhost` in dev, a PDF hosted outside Storage — takes the fallback, since the `download` attribute is ignored cross-origin.
- `/admin/*` — `AdminRoot` (auth provider) → `/admin/login`, and behind `ProtectedAdminRoute` (redirects to login, then back to the original URL; non-admin accounts see a "no permissions" message): `/admin` (events list, create event, per-event voting switch) and `/admin/:eventSlug/{papers,papers/bulk-upload,fields,fields/:fieldId,voters,voters/bulk-upload,results,screensaver}` (tabs in `AdminEventLayout`: Papers, "Campos" (`AdminFields.tsx`: define the event's fields) and then one tab per list field (`AdminFieldOptions.tsx`: its options with per-option paper counts and colors), generated from the fields; `AdminPapers.tsx`'s table has a column per field, sortable headers (fields, title, votes, views, downloads; empty values last) and a multi-select filter per list field with a "(Sin valor)" option; the paper form renders one `AttributeInput` per field. `AdminEventLayout` also which also holds the voting open/closed switch, the "Explicaciones de búsqueda" switch (`searchExplanationsEnabled`, see "Búsqueda inteligente") and an "Editar evento" modal for name/`bannerUrl`/`backgroundUrl`; both are image uploads — `FileInput` straight to Firebase Storage under `events/{eventSlug}/images/`, max 5 MB, via `uploadEventImage`/`deleteEventImage` in `storageService.ts` — not plain URL fields). The `screensaver` tab (`AdminScreensaver.tsx`) holds the enable switch + idle/photo-duration seconds (switch commits instantly, the two `NumberInput`s commit together via an explicit "Guardar" button) and a table of photo/video items (`FileInput` upload, manual numeric `order`, like a list field's options). `/` redirects to `/admin`; anything else is `NotFoundPage`. `admin` is a reserved event slug because static routes win over `/:eventSlug`.
- Admin behaviors worth knowing: new events start with voting **closed**; slugs are immutable (they are the doc id) and events cannot be deleted from the UI (votes can't be cleaned from the client); a paper with votes can't be deleted (reset the event's votes first); deleting a field or a list option removes its value from the papers that had it; results has a ranking, an audit list of votes, and "Reiniciar votos" (typed confirmation → `resetVotes`).
- Bulk upload (`components/admin/BulkUploadPanel.tsx`, generic over the row payload): download template → pick .xlsx → per-row validation preview (OK / SKIPPED / ERROR) → import in batches → downloadable report. Papers (`title, authors, institution, urlPdf` + one column per event field, headed by the field's label; authors and multiselect options separated by `;`; list values are option names and an unknown one is an error, required fields can't be empty, titles that already exist are skipped) and voters (`idNumber, fullName, active`; upsert by cédula).

### i18n (public site only; `/admin` is not translated)

- `i18next` + `react-i18next` + `i18next-browser-languagedetector`, initialized once in `src/i18n/index.ts` (imported from `main.tsx`). Detection order: `localStorage` (key `i18nextLng`, set when a visitor uses the switcher) → `navigator` language → `fallbackLng: "es"`.
- Translations: `src/i18n/locales/es.ts` (source of truth) and `en.ts`. `en.ts` is typed as `typeof es` with values widened to `string`, so adding/renaming/removing a key in one file without doing the same in the other is a **type error**, not a silent missing key at runtime.
- `LanguageSwitcher` (ES/EN `SegmentedControl`) lives in `PublicShell`'s header — public pages only, never rendered in `/admin`.
- Only interface strings are translated (buttons, labels, error messages, including the `castVote` error text, which the client now maps by `VoteError.code` instead of showing the Cloud Function's raw Spanish `error.message`). Content admins type in — event names, field labels and option names, paper titles/authors — is never translated; it renders as-is regardless of the selected language.

### Notable conventions

- Code comments are in Spanish. Admin-panel UI strings are hardcoded Spanish literals (not in scope for i18n). Public-site UI strings go through `t("namespace.key")` (see i18n section) — add new public-facing copy to both `es.ts` and `en.ts`, never as a literal in a public component.
- The Firebase web config is not secret; access control lives in Firestore rules and the functions. `netlify.toml` whitelists the API key from Netlify's secret scanner, and the `VITE_FIREBASE_*` vars must also be set in Netlify's environment (`.env.local` is not deployed) — without them the app crashes at startup (`auth/invalid-api-key`).
- No more hardcoded ACHO branding: the app-install QR codes and their promo copy (previously in `PosterDetail`) were removed on purpose, and the banner has no ACHO-logo fallback anymore — `PublicShell` renders a `Skeleton` placeholder (fixed height) when an event has no `bannerUrl`, instead of defaulting to any image. The banner and landing background remain per-event (see above).
- Speakers (conferencistas) and a bulk attendee/account importer existed in an earlier, Mongo-backed version of this app and were removed on purpose — they don't fit the Firestore model (paper authors live in `Paper.authors`; voters are the `voters` roster, no accounts). Don't re-add either without being asked.
- Deployment: frontend on Netlify (`netlify.toml`; `public/_redirects` rewrites everything to `index.html` for SPA routing); backend on Firebase.
